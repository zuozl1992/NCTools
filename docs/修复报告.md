# 修复报告

审查基线：2026-09-29 的现行 QML/C++ 构建版本。按上一轮问题清单逐项记录。

| 编号 | 问题 | 修复 | 状态 |
| --- | --- | --- | --- |
| 1 | 文件发送过早报告完成 | 等待待写队列清空，并在连接切换、断开或发送失败时终止；限制待写队列增长。这里的“完成”表示本机待写队列清空，不代表远端应用已确认接收。 | 已修复 |
| 2 | UDP 大报文截断 | 根据数据报实际长度分配接收缓冲区。 | 已修复 |
| 3 | 文件读取错误被报告为完成 | 分别处理 `read()` 的负值与零值；负值终止发送并报告失败。 | 已修复 |
| 4 | TCP Server 断开客户端后保留 socket | 在断开和关闭路径延迟销毁客户端 socket。 | 已修复 |
| 5 | UDP 一次只读取一个待收报文 | 循环读取直到待收队列为空。 | 已修复 |
| 6 | 串口高级设置打开时显示固定默认值 | 各选项从当前设置映射索引，并在每次打开时重新回填。 | 已修复 |
| 7 | 重启后不恢复上次连接模式 | 控制器初始化读取已保存的模式；不自动打开连接。 | 已修复 |
| 8 | 切回串口后端口列表可能不刷新 | 在串口对象和信号连接完成后主动刷新端口列表。 | 已修复 |
| 9 | 定时发送状态与界面不同步 | 启动时检查是否有待发内容；运行状态由实际定时器提供，失败后同步复选框。 | 已修复 |
| 10 | C++ 端口参数缺少范围检查 | TCP Server、TCP Client、UDP 本地端口入口拒绝 0 和超过 65535 的值。 | 已修复 |
| 11 | 发送失败时清空输入 | 发送接口返回结果；界面只在成功时清空，底层写入错误转发具体错误。 | 已修复 |
| 12 | 快速发送漏计 TX 字节 | 成功写入后增加发送字节计数并通知状态栏。 | 已修复 |
| 13 | 客户端数量属性始终为 0 | 控制器读取 TCP Server 的实际客户端数并转发变化信号。 | 已修复 |
| 14 | 显示文本无限增长 | 显示文本限制为最近 1 Mi 个字符。 | 已修复 |
| 15 | 设置测试未隔离持久配置 | 测试启用 Qt 测试模式并验证路径位于 `qttest`，保存/读取使用该路径。 | 已修复 |

附带修正：将 `enable_testing()` 移到根 CMake 文件，使根目录 `ctest` 能发现全部测试。

发布脚本修正：

- 修正应用图标路径，使用 `src/app/AppIcon.icns` 和 `src/app/control.png`。
- 保留旧 DMG，当前 DMG 使用日期时间命名。
- 发布过程改为在 `/tmp` 临时目录完成 Qt 依赖部署、清除 Finder 元数据、深度签名和签名校验，再生成 DMG；避免 SynologyDrive 对 Bundle 写入 Finder 元数据导致签名失效。
- `macdeployqt` 不可用时直接报错；完成后使用 `codesign --verify --deep --strict` 校验应用。
